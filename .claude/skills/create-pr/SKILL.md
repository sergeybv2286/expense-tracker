Задача: $ARGUMENTS

Аргументы: если первое слово совпадает с именем существующей локальной ветки (`git branch --list`), это ветка, для которой создаётся PR; остаток строки — заголовок или описание PR от пользователя. Если первое слово не совпадает ни с одной веткой, вся строка — это заголовок/описание, а ветка берётся текущая (`git branch --show-current`). Если аргументов нет вовсе, ветка — текущая, а заголовок/описание сформируй сам по истории коммитов.

Порядок действий:

1. Определи целевую ветку по правилам выше. Если это `main` — останови работу и сообщи, что PR из `main` в `main` не создаётся.
2. `git status`: если есть незакоммиченные изменения, останови работу и попроси пользователя сначала закоммитить или отложить их (stash) — этот skill сам ничего не коммитит.
3. Если целевая ветка не текущая, переключись на неё (`git checkout <branch>`), только когда рабочее дерево чистое (см. шаг 2).
4. Убедись, что ветка создана от актуальной `main` и есть коммиты, которых нет в `main`: `git log main..<branch> --oneline`. Если коммитов нет — сообщи и останови работу, PR создавать не из чего.
5. Запусти skill `/verify`. Если он падает — останови работу, покажи ошибки и не создавай PR, пока они не исправлены.
6. Запушь ветку: `git push -u origin <branch>` (или без `-u`, если upstream уже настроен — проверь `git status -sb`).
7. Собери заголовок и описание PR:
   - Заголовок: то, что передал пользователь в аргументах, либо (если не передано) — осмысленная фраза на английском в стиле Conventional Commits, обобщающая коммиты ветки.
   - Описание: секция `## Summary` с кратким списком изменений по коммитам (`git log main..<branch>` и `git diff main...<branch> --stat` для контекста), секция `## Test plan` с чек-листом того, что проверено (`pnpm typecheck && pnpm lint` — отметь как выполненные, раз шаг 5 прошёл).
   - Заверши описание строкой атрибуции:
     ```
     🤖 Generated with [Claude Code](https://claude.com/claude-code)
     ```
8. Создай PR через `gh pr create --base main --head <branch> --title "<заголовок>" --body "$(cat <<'EOF'
<описание>
EOF
)"`.
9. Покажи пользователю ссылку на созданный PR из вывода `gh pr create`.

Не выполняй push и создание PR без явного запуска этого skill пользователем — это соответствует правилу CLAUDE.md о том, что push и PR делаются только по явной просьбе.
